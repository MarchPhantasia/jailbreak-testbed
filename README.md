# Jailbreak Testbed

**Replayable, budget-accounted experiment infrastructure for multi-turn LLM attack research.**

一个可回放、按预算计账、可归因的实验基础设施，用来回答一个问题：**在固定的目标模型调用预算下，哪种设计真的提高了成功率。**

> 状态：**设计阶段（v1.1）**。本仓库当前只有规格与决策记录，没有任何可执行代码。
> 目标是先把契约与实验口径定死，再动手实现——契约改一次的成本，比实现改十次便宜。

---

## 这个仓库是什么

- 一套**实验基础设施的规格**：数据契约、接口契约、运行时序、预算规则、分析方法、里程碑。
- 一个**可评审的设计**：每个关键决定都有一条 ADR（`docs/adr/`），写明被否决的替代方案。

## 这个仓库不是什么

- 不是攻击工具集合。仓库不包含任何攻击载荷、绕过模板或可直接运行的攻击字符串。
- 不是某个已有项目的分支。全部实现将从零开始；外部项目仅作设计参考（见 `docs/adr/0001`）。
- 不是 benchmark 排行榜。它提供的是"如何公平比较"，不是分数本身。

## 目标函数

**在固定 `target_calls` 预算下，提高被判为成功的比例（ASR@budget）。**

其余指标都是护栏，用来防止"提升是假的"：

| 护栏 | 防止什么 |
|---|---|
| `support` / `dependence` | 答案变好看，但从目标拿到的信息没变多 |
| 成本四元组（target / judge / tokens / wall-clock） | 多花调用买来的成功率被当成方法优势 |
| 双裁判 + 人工切片 | 判据漂移冒充方法改进 |
| 配对差值 + 置信区间 | 噪声被当成效应 |

## 仓库结构

```
docs/
  README.md            评审指南（先看这里）
  spec/                规格：目标、契约、运行时、实验、分析、里程碑、统计
  adr/                 架构决策记录（含被否决的方案）
  protocol/            评测协议：rubric 规范与判分流程
spec/rubrics/          冻结的 rubric 示例（版本化）
configs/               实验配置示例
```

## 怎么评审

按 `docs/README.md` 的顺序走，大约 30 分钟。最需要挑刺的是两处：

1. `docs/spec/02-contracts.md` —— 接口一旦定下，后面所有实现都要服从；
2. `docs/spec/04-experiments.md` —— 实验设计能不能支撑"比基线更好"这个结论。

## Intended use

本仓库面向对**自有或已获授权的模型**做安全评测的研究者。它提供实验组织方式与度量口径，不提供攻击能力本身；能否运行取决于你自行配置的模型端点与数据。
