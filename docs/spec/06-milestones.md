# 06 里程碑

每个阶段必须产出一个数；没有数不算完成。

| 阶段 | 交付 | 验收（硬标准） | 工期 |
|---|---|---|---|
| **M0** | L0 日志 + L1 账本 + 回放器 | 人工构造一条 episode，能从日志重建状态与指标；`restore`（恢复当时状态）与 `recompute`（用新抽取器重算）两种模式结果可区分 | 3d |
| **M1** | 接入层 + 缓存 + `SessionMode` | 同一请求第二次命中缓存时 `served=false` 且 `budget_after` 不变；两种会话模式可切换 | 3d |
| **M2** | 状态层 + 最简方法（单轮改写）+ 20 条 | 出 ASR 与账本；状态可从事件重建 | 4d |
| **M2.5** | **忠实基线**（参考实现的搜索规则：前沿选择 + 混合评分 + 贪心深扩 + 终止判据） | 同数据上复现出与参考论文同量级的 ASR（允许差距，但必须能解释） | 6d |
| **M3** | 判定层：rubric 加载 + 双裁判 + 切片工具 | 100 条上 κ 有数；在线/离线判定分离可验证 | 4d |
| **M4** | B0–B4 首轮（各 50 条） | 配对差值 + CI + 成本账本 | 6d |
| **M5** | 分析：support/dependence 四格 + 失败分类 | 20 条轨迹上给出四格分布与噪声带 | 5d |

## M2.5 是硬门槛

如果基础设施表达不出参考实现的搜索规则（前沿选择 + 混合评分 + 贪心深扩 + 终止判据），那么"比基线更好"这句话没有意义。

表达不出来时的两条退路，必须选一条并写进 ADR：

1. **改契约**（扩展 `Frontier` / `Scorer` 的能力边界），再重跑 M2；
2. **放弃比较**，把项目定位改为"独立的实验台 + 方法探索"，不声称相对优势。

## 防呆规则

- M2 未跑出第一条真实 episode 前，不写第二个方法。
- 每阶段结束必须有一个数（哪怕很难看）。
- "只差一点点就能跑"是 schema 有问题的信号：改 schema，不要打补丁。
- 任何阶段新增的临时脚本，必须在当阶段结束前决定"进仓库还是删掉"。

## 风险登记

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 搭建期过长，迟迟无数据 | 高 | M0+M2 压到 7 天内出第一条 episode；方法先用最简的 |
| R2 | 结构化状态反而更差 | 中 | 这本身是结论；保留原样拼接作为退化路径 |
| R3 | 状态抽取错误（幻觉进 `F`） | 高 | 强制 `src_events` 非空 + `fidelity` 告警 + 30 条抽检 |
| R4 | 裁判漂移导致结论翻转 | 中 | 双裁判 + 200 条人工切片 + E3 分类 |
| R5 | 装配择优被裁判格式偏好带偏 | 中 | 报"人工最优"与"裁判选中"的一致率 |
| R6 | 预算被绕过（组件偷偷调用） | 中 | 所有调用只走 `BudgetGuard`；离线审计脚本核对 `served` 计数 |
| R7 | 缓存把重复采样变成读取，方差虚低 | 中 | `served` 与 `logical` 分列；方差只用独立采样 |
| R8 | 服务端会话让"回退"名不副实 | 中 | `SessionMode` 进配置并写进结果 |
