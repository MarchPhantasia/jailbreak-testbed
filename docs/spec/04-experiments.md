# 04 实验设计

## 五个配置（都跑在忠实基线上）

| 配置 | 改什么 | 回答什么 |
|---|---|---|
| **B0** 基线 | — | 当前模型与数据条件下的参考 ASR |
| **B1** + 等长自然语言摘要历史 | 状态 = 摘要 | 单纯缩短历史有没有收益 |
| **B2** + 结构化状态（F/O/X） | 状态 = 结构化 | 结构化是否比摘要更有用 |
| **B3** + 新装配（事实清单 + k 候选） | 只动 `Assembler` | 装配的独立贡献 |
| **B4** + B2 + B3 | 两项同改 | 是否互补（需超过 max(单改) 才算） |

**为什么必须有 B1**：没有摘要臂，B2 的增益无法区分"结构化有用"与"上下文变短有用"。这一臂多花两天，省掉会让 H2 无法成立。

## 冻结清单（除被测项外全部固定）

搜索规则（`Frontier`）· 生成模型 · 打分策略（`Scorer`）· 在线停止判据 · 裁判 · rubric 版本 · 数据子集 · 预算 · 种子 · 会话模式。

**跨 episode 记忆默认重置**；要测记忆时单独一组，并在配置里写死"共享范围"。

## 四个假设（按"提高 ASR 的可能性 × 成本"排序）

| 编号 | 假设 | 机制（为什么可能提高 ASR） | 必须固定 | 护栏 |
|---|---|---|---|---|
| **H1** | 装配改为"事实清单 + k 候选择优"能提高 ASR | 不增加目标调用，只把"一次装配 + 两处截断"换成"清单化 + 多次抽样取优" | 轨迹不变（同一批轨迹离线重装） | 候选分数方差 vs 提升幅度；k 的边际收益与 token 成本 |
| **H2** | 结构化状态（F/O/X）比等长摘要更能提高 ASR | 有限上下文下，显式分离"已知/待办/已失败"减少重复决策 | 摘要长度、抽取器、预算、搜索规则 | `fidelity` 分布（`inferred` 比例）、重复提问率、抽取成本 |
| **H3** | 打开失败记忆（跨 attempt）能提高 ASR | 回退后失败原因仍可用，避免重复同一方向，省下预算换新尝试 | 记忆上限、检索键、生命周期 | 重复失败率、记忆命中率、上下文膨胀 |
| **H4** | 规则化停止能提高 ASR | 把"判早了"的预算回收给后续尝试 | 停止阈值 | 平均轮数、每成功所需 target 调用 |

## 结果怎么表述（措辞纪律）

- B3 只能说"**在目标调用相同、装配 token 上升 X% 的条件下，ASR 提高 Y**"，不能说"同预算下更好"。
- B4 若不超过 `max(B2, B3)` 的 1.5 倍，结论写"两项在争用同一份收益"，不写"互补"。
- 任何一组若 `support` 显著下降而 ASR 上升，标注为"**增益可能来自生成侧补写**"，并在结论里单列。

## E3：判据敏感性（护栏，不是主结果）

裁判翻转不先当 bug，先分类：

| 类型 | 判据 | 处理 |
|---|---|---|
| 判据设计分歧 | 同一回答被两种判据合理地判成不同等级 | 是设计问题，记录并解释 |
| 判据不稳定 | 同一判据重跑同一样本翻转 | 是可靠性问题，需修判据或提高确定性 |

两类分开报；不要"修到不翻转"再继续比方法。
