# 独立研究框架完整开发方案 v3.5

整合日期：2026 年 11 月 10 日（v3.5：新增 §15.3.2 episode 结果判定顺序，固定 `unscored` 与 `INSUFFICIENT_EVIDENCE` 的层面区别与 success / failure / unresolved 的四步判定；§10.2、§12.1、§13 与 §15.3 规则 6 加交叉引用。v3.4 的指标表修订、v3.2 的六处口径、v3.1 的 jailbreak 定位与部署边界保持不变）。

本文是可独立阅读的开发规格，覆盖目标、模块、数据契约、分支执行、证据与保真度、分阶段预算、异常恢复、数据集、实验和开发验收。当前交付为方案文档；文中的代码目录、接口和命令均为待实现设计。

研究对象是一个越狱（jailbreak）攻击框架：在给定 Target 查询预算下，把对齐模型的"拒绝"推成"可用的服从性输出"，并对最终越狱答案计 ASR。CKA、R³、TAP 等工作是同一问题上的局部设计参考，不定义本框架，也不预设本框架优于任何方法。框架不产出防御手段，不做对齐训练，也不训练拒答检测器。

## 1 目标与实施范围

系统由本地攻击者模型理解当前越狱进度、提出动作，程序负责校验、执行和限制资源。越狱答案所需的新增操作性细节主要取自 Target 的服从性输出，本地模型承担规划、阅读、抽取、推理和组织。

| 目标 | 具体要求 |
| --- | --- |
| 越狱完成 | 在固定 Target 查询上限下形成最终越狱答案，用冻结判据评价 |
| 信息可追溯 | 保存 Target 原文、实际请求、加工输入输出及答案出处 |
| 拒答可观测 | 拒答、软拒答、部分服从、完整服从分别记账，作为过程指标与机制解释的输入 |
| 错误可区分 | 内容来源、本地处理保真度、内容真实性分别记录 |
| 组件可替换 | 状态、搜索、评分、装配、选择与评价通过明确接口衔接 |
| 运行可恢复 | 已记录状态可恢复，不重新询问模型来猜测当时状态 |
| 成本可检查 | 所有模型调用经统一入口，记录预算、实际用量与未知项 |
| 结论可检验 | 通过框架内部配置与消融研究组件作用，不预设正向结果 |

### 1.1 威胁模型

| 角色 | 定义 |
| --- | --- |
| 受害模型（Target / victim） | 带对齐与拒答策略的目标模型；只通过 HTTP 访问，攻击者不读写其权重与日志 |
| 攻击者能力 | 自由构造每轮提示、历史视图（View）与会话模式；可在本地做任意规划、抽取、评分与装配；不假设白盒、梯度或权重访问 |
| 攻击者资源 | 固定 `target_calls` 预算；本地算力另计并照实报告 |
| 成功判据 | 冻结的 Judge_eval 对 episode 最终答案的判定，即 jailbreak 成功 |
| 观测对象 | Target 的拒答 / 软拒答 / 部分服从 / 完整服从行为，以及最终答案的操作性内容 |

Target 的拒答不是"任务失败"，而是过程观测量：同一攻击器在不同拒答强度下的拒答率—服从率曲线，与最终 ASR 分别报告；两者关系在明确的样本范围、服务配置与预算条件下解释，不预设前者必然转化为后者。

### 1.2 研究口径

| 项目 | 确定的口径 |
| --- | --- |
| 主目标 | 相同 Target 查询预算下，经冻结评估程序判定的 jailbreak ASR |
| 成功对象 | episode 最终选出的越狱答案；同时保留 Target 原始回答（含拒答与部分服从片段），两者分别统计 |
| 信息要求 | 越狱答案中新增的操作性细节（步骤、参数、材料、路径、时序）应关联可定位的 Target 材料；攻击器先验知识的补写单独标记，不并入 Target 贡献 |
| 拒答口径 | 单轮回复的拒答、软拒答、部分服从和完整服从，以当前子请求为参照；其对原始有害请求的完成度另行记录。episode 成功以最终选中答案是否完整满足原始请求，并符合冻结的可用性与 Target 来源规则为准，不要求任一次 Target 回复独立完成整个原始请求 |
| 因果要求 | 通过预先声明的证据删除、替换或前缀干预，评估最终答案及成功概率对 Target 材料的依赖。结论限定于具体干预、可见信息范围和评估配置，不将干预后的成功或失败直接等同于信息的真实来源 |

首阶段包含纯文本、黑盒 Target（攻击器只看得到它的拒答与服从行为）、外部推理服务接入、线性与分支执行、episode 内记忆、答案装配、评价与回放。训练、微调、多模态、白盒表征分析及跨 episode 技能库留作后续研究；拒答加固、对抗训练等防御侧对照另设 profile，不进入本版方法比较。

部署不在本项目范围内：权重下载、量化、推理引擎安装、GPU 配置、服务启动与吞吐调优由研究者自行完成，也不进入仓库交付物；本框架只连接已经能应答的 endpoint，其余全部是客户端与实验编排工作。

## 2 已确定的边界与实验前待定项

| 已确定 | 执行含义 |
| --- | --- |
| 独立架构 | 核心验收不要求实现 CKA 或其他指定算法 |
| 本地 LLM Controller | 模型理解状态并提出动作，Engine 校验与执行 |
| 一个模型可承担多个角色 | 分开构造上下文，不要求多个本地大模型 |
| 保留分支能力 | 线性闭环是开发起点，正式方法可选择分支搜索 |
| Target 提供主要操作性细节 | 本地推测单独保存，不能冒充 Target 证据；补写产生的成功在报告中单列，不用单一 ASR 掩盖来源 |
| 保留最终 Judge_eval | 冻结答案后按固定判据评价，结果不反馈当前搜索 |
| 支持分阶段预算 | 同一模型可因阶段不同使用不同配置 |
| 原文始终保留 | 摘要、抽取、装配结果均可回到原始材料复核 |
| 正式在线实验关闭响应缓存 | 缓存命中不能当成独立生成样本 |
| 开发与测试隔离 | 具体任务 ID、数据版本、划分和配置均形成清单 |

以下项目在实验启动时选择并冻结：搜索与分支选择策略、节点打分方式、停止规则、各阶段思考档位和额度、候选数及选择规则、是否增加核对调用与调用顺序、离线抽检工作量、采样种子和确认性比较。

设计倾向给最终答案整理较充分的思考空间，但不在本文预设各阶段档位或数值。更多思考不保证正确，答案更长也不代表思考更充分。

研究者现有资源为一张 A800 80GB，只承载攻击者侧策略模型。首选候选为 `JonathanColetti/Qwen3.8-27B-Uncensored`，备选为 `huihui-ai/Huihui-Qwen3.8-27B-abliterated`，BF16 为此前讨论的初始候选精度；这两者决定攻击器自身会不会被对齐拦住，而不是 Target 的拒答强度。Target 由研究者另行提供 endpoint（官方 Qwen3.8-27B 或其他带拒答策略的对齐模型）。框架只记录部署侧最终提供的权重与服务信息，不将仓库、精度或引擎写死在实现中，也不据此保证角色能力。

## 3 总体架构

```text
ExperimentRunner / CLI
  │  冻结有害请求、配置、版本与预算
  ▼
Engine ─────────── Controller LLM
  │                     │
  │                提出结构化 Action
  ├── StateBackend / HistoryView
  ├── Frontier / SearchPolicy / Scorer
  ├── Assembler / CandidateSelector / Judge_online
  └── RecoveryPolicy
  │
  ▼
ModelGateway + BudgetGuard + StageBudgetPolicy
  ├── 攻击者侧策略模型（本地，已由研究者启动）
  ├── TargetClient（可包裹 Defense 包装）
  └── 已配置的其他模型服务
  │
  ▼
EventStore / 请求响应原文 / 状态快照 / 成本记录

episode 结束、最终答案冻结
  ▼
EvaluationRun → Judge_eval → 指标与报告
                     └── 可选离线审计与反事实分析
```

Controller 不能绕过 Gateway 调模型、直接修改预算、删除事件或任意改写正式状态。所有模型调用，包括评分、抽取、候选择优、恢复、接入探针及离线分析，都经统一入口并记账。

语义角色不等于独立模型或独立调用：一个服务可以承担多个角色，同一次调用也可能按明确配置完成多个相关步骤。配置与日志必须说明实际发生了哪些处理，不能按模块数量虚报调用数量。

## 4 模块接口与职责

| 模块 | 输入与输出 | 责任边界 |
| --- | --- | --- |
| DatasetAdapter | 固定来源 → Task 与数据清单 | 保留有害请求原文、必要上下文、来源与版本 |
| Engine | Action、状态与预算 → 执行事件 | 校验动作、状态版本、引用和服务能力 |
| Controller | 有害请求、允许读取的状态、前沿与预算 → Action | 提出下一步攻击动作，不直接操作外部服务 |
| StateBackend | 原始观察与已配置处理 → 状态记录 | 支持原文、摘要、F/O/X 等表示，保留加工链 |
| Frontier | 节点、候选、状态与评分引用 → 可选前沿 | 保存替代路径，不自行决定事实真假 |
| SearchPolicy | 前沿、观察、评分和预算 → 选择与扩展决定 | 策略独立配置，不绑定 UCT 或某种回传公式 |
| Scorer | 指定候选或已观察节点 → 评分记录 | 说明评价对象、依据和未知项，不将未知写成零 |
| Assembler | 有害请求与选定证据 → AnswerCandidate | 组织 Target 服从性输出中的细节，保留条件、否定、版本、冲突和缺项 |
| CandidateSelector | 候选与冻结的在线标准 → 选中候选 | 不读取 Judge_eval 的最终结果 |
| Judge_online | 在线所需材料 → 继续、停止或未知反馈 | 为运行服务，不代表最终报告真值 |
| Judge_eval | 冻结的有害请求、答案、越狱判据与规定材料 → Verdict | 独立保存最终评价，不回写当前搜索 |
| RecoveryPolicy | 角色、调用状态与有效产物 → 有限恢复动作 | 不修改已发生的成本，不伪造完成状态 |
| ModelGateway | 调用请求与阶段策略 → 响应及用量 | 适配已有接口，保存实际消息和配置 |
| BudgetGuard | 资源请求 → 预留、结算或拒绝 | 每次调用前检查，全局限制分支与恢复消耗 |
| EventStore | 不可变事件 → 恢复与派生报告 | 事件是运行事实的主记录，账本由其聚合 |

接口状态至少区分 `OK`、`PARTIAL`、`REFUSED`、`INVALID_OUTPUT`、`TRUNCATED`、`TIMEOUT`、`TRANSPORT_ERROR`、`BUDGET_EXHAUSTED`。语义任务另保留 `INSUFFICIENT_EVIDENCE`。

是否愿意回答、格式是否有效、内容是否满足有害请求分别判断。不能仅凭拒绝关键词丢掉有效的部分产物——带拒绝前缀但给出可用细节，正是最常见的越狱过渡态；也不能把证据不足当成组件故障。

## 5 核心数据契约

### 5.1 Task 与 Episode

Task 保存 `task_id`、数据来源、`primary_dataset`、`source_aliases`、上游 ID、原始有害请求、必要上下文、类别、来源行定位、数据 revision、profile、split、`duplicate_group_id`，以及仅评价侧可读的越狱判据与参考材料引用。

Episode 表示一个有害请求、一个攻击方法配置、一份预算和一个采样种子的一次完整越狱尝试。保存 `episode_id`、Task 引用、数据与划分清单校验值、方法版本、`config_hash`、模型与部署记录、SessionMode、预算、阶段策略、核对策略及恢复策略版本。

数据划分 seed 与模型采样 seed 分开。行为配置的解析后值写入清单，凭据除外。配置变化不能复用同一个指纹。

### 5.2 AgentState 与 HistoryView

```text
AgentState
  facts        按当前证据规则保存的命题，不等于已验证真实
  open         尚未满足的越狱要素及缺口
  failed       失败尝试、原因、事件出处与适用范围
  hypotheses   本地提出、尚待验证的推测
  budget_left
  source_event_seq

HistoryView
  view_id / parent_view_id
  visible_message_refs
  session_mode
```

这些字段是结构化状态配置的表示，不要求原文组也强制抽取一份事实清单。原文组直接保留规定范围的完整消息；摘要组和 F/O/X 组记录实际加工过程。

攻击者状态与 Target 可见历史可以有意不同，但二者的版本关系必须清楚。状态快照不能依靠未记录的模型内部记忆恢复。

### 5.3 Evidence 与命题

Evidence 保存证据 ID、原始事件 ID、消息角色、原文片段、范围与原文校验值。范围统一采用 Unicode code point 的半开区间；跨语言代码显式转换，不混用 UTF-16 偏移。

| 命题字段 | 含义 |
| --- | --- |
| `fact_id / text` | 命题标识及文本 |
| `origin` | target_response、input、controller_hypothesis 或 derived |
| `evidence_ids` | 与命题关联的原始材料 |
| `fidelity` | 形成方式：verbatim、paraphrase 或 inferred |
| `support_status` | 与引用材料的关系：entailed、contradicted、insufficient 或 unknown |
| `qualifiers` | 条件、否定、时间、版本、对象和不确定性 |
| `dependency_fact_ids` | 推导依赖的其他命题 |
| `processing_refs` | 实际发生的抽取、概括、装配阶段及调用 |
| `extractor_ref` | 采用抽取时的模型、模板、精度与版本 |
| `fidelity_status` | 可选审计：preserved、altered、uncertain、not_assessed 或 not_applicable |
| `truth_status` | 可选审计：correct、incorrect、unknown 或 not_assessed，附判断依据 |

形成方式、语义保真与事实正确性不是同一个量。逐字截取也可能遗漏上下文；有出处不能代替蕴含检查。未作审计时不填写虚构的正确性结论，保留审计字段不意味着必须增加一次在线模型调用。

### 5.4 Action、节点与候选

Action 保存动作类型、参数、依据的事件或命题、`based_on_state_seq`、节点与 View 引用及简短依据。

最小闭环支持 `ASK_TARGET`、`ASSEMBLE`、`STOP`。分支执行支持节点选择；一次 `ASK_TARGET(parent_node_id, query)` 从指定父节点推进，多个子节点形成分支。具体是独立选择动作还是与查询动作合并，由实现接口明确记录，不要求增加一个模型调用。

SearchNode 保存 `node_id`、`parent_node_id`、State 快照、View、动作与实际请求响应引用、评分记录、消耗和节点状态。根节点可以没有 Target 响应。

本地提出但尚未执行的候选单独记录为 proposal，不是 Target 观察，也不能提供事实证据。预期价值与执行后评分分开保存。

AnswerCandidate 保存答案、输入证据包、输出主张与证据映射、推导依赖、缺项、装配配置和阶段策略、处理引用、备用渲染标记与结束状态。

Verdict 保存评价运行 ID、有害请求及判据版本、答案 ID、评价器与配置、类别、覆盖情况、可用性和依据。来源、保真度、真实性的审计结果按主张关联，不揉成一个成功分数。

### 5.5 Policy 与清单

StageBudgetPolicy 保存阶段映射、公共配置、继承规则、服务参数映射与能力信息。VerificationPolicy 保存额外核对是否启用、对象、触发条件、预算归属与顺序。二者在实验启动时填写并冻结。

DatasetManifest 保存来源 URL、数据 revision、原始文件 SHA-256、适配器与筛选版本、划分 seed、任务 ID、重复组、纳入和排除记录。

## 6 信息来源与整理保真度

本章约束并审计最终答案的信息来源，避免把攻击器先验知识补写与 Target 实际提供的内容混为一谈。需要新增的操作性细节应关联可定位的 Target 材料；原始请求中已有的信息单独标为 input。允许基于已有材料进行计算、推导和组织，但不能隐含新增领域前提。最终完成情况与信息来源分别记录，并按预先声明的规则形成 ASR。

### 6.1 信息进入状态和答案的规则

1. 原始有害请求与公开上下文标为 input，不计作 Target 新提供的信息。
2. 新增操作性命题（步骤、参数、材料、路径、时序、约束）关联可定位的 Target 材料；引用存在与语义支持分别记录。
3. 本地知识或猜测进入 hypotheses，不自动升级成 Target 证据。
4. 允许计算、推导和重组，但列出依赖，不隐含新增领域前提。
5. 条件、否定、版本、矛盾与缺项保留相应标记，不为覆盖率自由补全。
6. Target 在回复中提供某内容，不代表该内容正确、可用或由其首次独立产生。`support_status` 记录加工后主张与引用材料之间的支持关系；`fidelity_status` 记录本地加工是否保留原意；`truth_status` 记录有依据的真实性判断。内容是否足以完成原始有害请求，由冻结的越狱判据评价。未核验时保留相应的未知或未评估状态，不凭流畅度作肯定判断。

Target 提供但不正确的内容仍归属 Target，与本地概括、抽取或装配造成的失真分别报告。引用存在、原意保留、事实正确和任务完成不能互相替代。

若 Controller 先提出某编号，Target 只是承接前提，日志可以说明 Target 回复包含该编号，但不能据此认定该信息独立来自 Target。因果来源另用干预研究。

### 6.2 区分 Target 内容错误与本地处理错误

| 情况 | 记录方式 |
| --- | --- |
| Target 给出错误库位，本地忠实保留 | 来源仍为 Target；有可靠参照时另记真实性错误 |
| Target 说“第一次需要登记，以后不用”，本地写成无条件的“办理需要登记” | 记录条件丢失，关联实际加工阶段，属于本地处理错误 |
| 某阶段直接使用完整原文，未概括或抽取 | 不将该阶段计为发生概括失真，相应转写审计可为 not_applicable |
| 保留了引用，但引用不支持加工后的主张 | 不能统计为忠实保留的 Target 内容；保存原文与加工结果供复核 |

条件丢失是一种需要检查的失效模式，不预设已经发生，也不预设是主要瓶颈。直接使用完整原文时，上述概括失真不适用于未发生的步骤；后续理解或装配若出错，按实际阶段另记。

保真度抽检以原文与加工结果成对进行。统计分母为实际发生并接受检查的相应处理步骤，另报抽检覆盖；未检查、未发生与已保真不能混为一类。

## 7 分支、节点选择与会话控制

### 7.1 分支执行约束

分支用于保存不同的候选方向。Frontier 与 SearchPolicy 分开，节点数据结构不包含对某种算法的强制假设。选择、扩展、深度与宽度限制、回传及停止规则都须在运行前声明。

同一父节点下的子节点拥有独立的正式状态。某分支得到的材料不能通过共享可变对象悄悄进入兄弟分支。允许读取的 episode 内失败记忆按统一范围提供，并记录其出处。

切换节点只改变后续执行依据，不能删除失败事件或退还任何已发生消耗。节点选择记录候选范围、评分依据、选中对象、策略版本和剩余预算。

跨分支证据利用属于单独实验变量。启用时显式记录证据选择与合并，核对实体、版本和条件兼容性；合并证据不等于 Target 在同一历史里看过全部分支。

### 7.2 评分器的作用

节点评分、最终候选择优、在线停止、最终评价是不同决策。Scorer 可采用模型判断、确定性记录或二者组合，不要求仅使用 ΔF、覆盖增量或某个特定评分公式。

评分记录应能说明对象、判据、可定位依据与未知项。事实数量、回答长度、拒绝关键词及模型自报信心，都不能直接等同于越狱进展。缺失评分为未知，不伪装成零分或失败惩罚。

保留评分器配置与提示版本，支持在已保存节点上作离线评分审计。节点评分如何影响实际选择，由 SearchPolicy 明确使用；结构化依据本身不保证模型判断正确。

### 7.3 Target 的两种会话模式

| 模式 | 能力与限制 |
| --- | --- |
| stateless | 客户端完整提交消息列表，可从选定节点构造新的 View；保存实际消息快照 |
| server_side | 服务端保留会话；只有服务真实支持分支、重置或等价操作时才能声明相应能力 |

本地修改 View 不等于服务端遗忘。TargetClient 拒绝不支持的操作并记录原因。

Event 永久保存失败尝试，新 View 可不再向 Target 提交它，而 Controller 在允许范围内仍读取其失败原因——让 Target 看不见死路，让攻击器记得死路。这是借鉴 R³ 的不对称记忆思想，不照搬其节点接受规则。跨 episode 记忆首版关闭。

## 8 分阶段思考预算与资源记账

### 8.1 同一模型的阶段配置

阶段与模型角色分别标识。定位、抽取、下一步规划、方向选择、最终装配、候选择优和评价可以有不同配置，同一个模型或角色可以服务多个阶段。

简单定位可采用较轻配置；规划、方向选择和最终整理可分配更多思考空间，具体档位与数值在实验阶段确定。最终整理围绕已有证据检查条件、否定、版本、矛盾和缺项，不凭本地知识补齐材料。

只映射推理服务已支持的控制项。不支持独立思考参数时如实记录；不能把提高输出长度上限视为已经增加实际思考，也不强制读取未公开的内部推理。

分别保存请求配置、客户端实际发送配置、服务公开报告的用量及其可用性。未指定阶段覆盖时继承明确记录的公共配置，不代表零预算。

### 8.2 查询与成本单位

主比较固定每个 episode 的 `target_calls` 上限，不要求每组实际调用次数相同，也不为填满预算发送无用请求。实际用量另报。

`target_calls` 计实际向 Target 服务发出的请求，包括拒答、后来丢弃的分支、网络重发和已发出但超时未知的请求——被拒的那次查询同样消耗攻击预算，拒答不能免费重来。尚未发出的预留可释放，已发出的查询不退款。

另记算法提出的 logical 请求。若本地 Defense 在发送前阻断，不虚报 Target 调用；请求到达远端服务后被远端过滤仍记录该次服务请求，底层模型是否生成以可得信息记录，未知时不推断。

| 资源维度 | 记录要求 |
| --- | --- |
| 调用数 | Target 与各非 Target 阶段分别记录 |
| token | 输入、输出及服务公开的推理用量；包含关系按服务定义去重 |
| 墙钟 | 单次耗时与 episode 总耗时分别记录，并发耗时不直接求和作墙钟 |
| 费用 | 可得时记录；缺失时不填零 |
| 配置上限 | 与实际用量分开，未提供 usage 的维度标 estimated 或 unknown |

BudgetGuard 使用 reserve → dispatch → settle；每次模型调用之前检查。恢复、评分、装配、选择与分析均不能绕过预算。用量不可观测时不能宣称该维度已经精确控制。

### 8.3 阶段成本与缓存

影响当前动作或答案的调用属于 online；结束后的重判、审计和反事实重算属于 analysis。接入探针作为独立 preflight 记账，不能进入 episode 的事实或样本，比较组遵守一致规则。

正式在线实验关闭响应缓存。回放或专门测试记录 cache_hit，区分 logical 与实际 served 调用；缓存结果不是新的独立样本，不能进入独立生成方差估计，也不能为某组免费增加 Target 信息。

比较状态、记忆或装配时固定阶段策略。研究阶段预算时将其单列为变量，同时报告本地总成本；只有额外控制本地总资源后，才能讨论相同本地预算内的分配效果。

## 9 既有模型服务的接入

优先接入 vLLM 或其他工具提供的兼容 HTTP 接口，也允许薄适配器。核心模块只依赖 ModelGateway，不依赖模型加载方式。纯客户端项目不因连接服务而必须安装 vLLM、CUDA 或权重加载库。[vLLM 服务接口](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)

| 调用配置 | 部署记录 |
| --- | --- |
| endpoint_id、protocol、base_url、served_model_name、api_key_env、超时、客户端并发、公共参数、角色映射 | 权重仓库与 revision、实际精度、引擎版本、模板校验值、上下文能力、thinking 与历史保留行为 |

部署记录来自研究者或服务返回，标明 operator_reported、api_reported 或 unknown。服务中的模型名称可能是别名，不能据此验证权重身份或精度，也不能把这些元数据当作加载参数发送。

接入检查仅确认连通性、模型名称、生成接口、输出解析、finish_reason、usage、公开推理信息与错误格式，不用于估计 Target 对基准请求的拒答行为；该检查记为 preflight，成本单列，不进入 episode 的事实或样本。有模型列表则使用，没有则通过实际请求检查；没有原生结构化输出时允许文本解析与本地校验。

Target 行为基线作为独立评测运行，使用预先声明的请求集合、输入方式、服务配置与标注协议，记录拒答、软拒答、部分服从及完整服从等指标。相关调用与成本单独记账，结果不作为攻击 episode 的免费上下文或证据；其确认性地位见 §15.3.1（默认描述性，除非单列为研究问题并预声明）。

角色能力校准及调试所用的基准原样样本来自开发池，并保留来源 ID 与重复组。留出测试集上的基线评测在协议冻结后开展，其结果用于报告，不回用于当前配置选择。Uncensored 标签与健康检查都不能证明规划和整理能力；"不拒答"只是必要条件，从不拒答但只会空泛重复的模型对 ASR 没有贡献。服务不可用时走已定义的错误与恢复路径；更换 endpoint 属于研究者的部署决定，写入新的部署记录并产生新的 `deployment_manifest_hash`。

同一服务的不同角色分开构造上下文。公开返回的推理文本可记录，但不是事实证据，也不能在状态对照中隐式充当额外完整历史；未公开的服务内部状态不要求获取。

## 10 答案装配与最终评价

### 10.1 装配和选择

Assembler 接收有害请求、选定材料及允许的推导，输出答案与主张级证据映射。缺项保留为缺项，不为完成格式自由补写新的操作性细节——补写会让 ASR 虚高：成功可能来自攻击器自身权重，而不是本次越狱带来的信息增量；具体归属按 §16 的干预协议判断，不在此处预设。

单候选是开发起点。多候选实验使用相同证据包，显式记录候选数 k、阶段策略、选择规则及全部成本；保留基础候选。候选池成功率与选择器找回率分别分析，二者的定义、分母与确认性地位见 §15.3.1。

### 10.2 四个评价位置

| 位置 | 判断对象 | 输出如何使用 |
| --- | --- | --- |
| 节点评分 | 局部候选或观察 | 由搜索策略用于选择与扩展 |
| 候选择优 | 已生成答案 | 决定保存哪个候选 |
| Judge_online | 当前在线结果 | 依配置继续或停止，允许未知 |
| Judge_eval | 冻结的最终答案 | 形成最终指标，不反馈当前搜索 |

Judge_eval 使用固定越狱判据与版本。若采用 A/B/C/D，只有 D 计完整成功，其余类别的含义在 rubric 中明确；评估不可用单独记 unscored，不硬塞进失败类别。

同一模型承担多个评价角色不保证误差独立，配置与报告披露同源情况，保留人工切片。在线停止原因 online_success 不等于最终评价成功。

单轮行为标签与最终答案类别使用不同的评价对象。某条回复可以完整回答当前子问题，但只提供原始请求所需的部分信息；多条部分信息也可能经过装配形成完整答案。

混合回应，例如包含拒绝表述但同时提供有效片段，其归类优先级在标注协议中固定。最终答案的完成度与来源合规情况分别记录；无法确定的项目保留未知状态，按预定义协议处理并报告覆盖率。若采用 A/B/C/D，D 对应最终答案满足本研究冻结的成功条件，不与单轮"完整服从"标签自动等同。

评价不可用记 `unscored`，但它本身不等于该 episode 进入 U：episode 结果按 §15.3.2 的顺序判定，已按冻结协议确定失败者不会因为没跑成 Judge_eval 而被计入 U。

### 10.3 保留最终 Judge 与可选核对

已有最终 Judge_eval 保留，同时保存 Target 原文和答案出处。是否额外核对、核对预算和顺序留到实验启动时决定，不默认每次装配后都增加反思或审稿调用。

若核对参与当前答案修改或选择，属于在线链，须在最终候选冻结前完成；冻结后的评价和审计不覆盖原答案。只有数据依赖与评价隔离是固定约束，额外核对的具体工作流不在本文预设。

## 11 组件拒答与异常恢复

组件拒答指本地组件未按其角色要求提供可用产物，与 Target 对请求的拒答分别记录。组件拒答可能增加本地成本、减少可执行动作或触发备用路径；其是否影响最终 ASR，以及影响大小，由恢复机制、预算限制和实际实验共同决定，不预设必然下降。因此它单独观测、单独报告，不并进 Target 拒答统计；在 §15.3.1 中列为描述性指标，可预声明为次要终点。

通用处理顺序：保存原始响应与成本 → 校验可用部分 → 保留最后有效状态和候选 → 执行预先声明的有限恢复路径 → 无法恢复则结束并记录原因。

| 角色 | 备用处理 | 不允许的处理 |
| --- | --- | --- |
| Controller | 校验已有合法待执行动作；或在证据允许时装配；否则保存并结束 | 编造新语义动作 |
| Extractor | 原文保留，材料待处理，沿用上一有效状态 | 伪装抽取完成，或丢掉原始观察 |
| Scorer | 按预先声明的已有分数或稳定次序处理，记录降级 | 未知写零分并回传失败惩罚 |
| Assembler | 保留已有候选；可按证据规则允许的命题作程序化渲染，真实性另评 | 无依据补写或自动记成功 |
| CandidateSelector | 使用事先规定的基础候选，记录降级 | 看过最终评价后再挑答案 |
| Judge_online | 记未知，按固定控制规则继续或结束 | 未知直接视为成功或路径失败 |
| Judge_eval | 保存 unscored，进入独立重判队列 | 默认 Target 已阻断该请求，或删掉样本 |

若启用 `rephrase_retry`，应明确其作用角色、输入对象、触发条件、调用上限、成本归属及策略版本。改变组件输入的重采样属于可能影响结果的策略变量，与网络或格式重试分别记录，并在配置对照中保持一致或单独研究。

组件上下文变化与 Target 的 HistoryView 变化分别记录。面向 Target 的新增查询仍通过正常 Action 与预算流程执行，不能因归入恢复机制而绕过 Target 查询限制。

网络与格式错误分别采用有限重试，既有初始建议为各至多一次；恢复也有 episode 总上限。未知是否完成的请求先记录已知状态，不盲目重发或退款。

同一权重切换角色不是独立备份，不要求第二个本地大模型；额外 endpoint 由研究者自行提供并在部署记录中登记。拒答恢复策略在各实验组保持一致，方法特有恢复单独作为变量。

恢复后成功正常进入结果，降级率另报；最终无答案仍在预定分母中。已有答案但最终评价不可用属于评估未知，与系统无答案区分。

## 12 一次 episode 的完整执行

### 12.1 执行流程

1. 从冻结数据清单加载 Task，保存实际输入、版本和解析后的配置。
2. 初始化全局预算、根节点、State、View 与前沿。
3. Controller 或配置的策略基于允许的信息提出动作，记录所用阶段配置与成本。
4. Engine 校验引用、状态版本、参数、预算及服务能力；无效动作记录为 rejected。
5. 若查询 Target，预留额度，保存实际 view_snapshot，发送请求并保存原始返回。
6. 按状态模式保留原文或执行所配置的加工，分别记账并写入 state_write。
7. 建立观察节点、保存评分与前沿变化；如切换分支，记录选择依据和新 View。
8. 若装配，保存证据包、所有候选、选择结果及已配置的在线反馈。
9. 达到停止条件或预算限制时，保留最终候选或无答案原因；Target 预算耗尽后只允许使用其他剩余额度处理已有材料。
10. 写入唯一 terminate，冻结最终答案，再通过独立 EvaluationRun 执行 Judge_eval。

正常结束只有一条 terminate。进程异常且尚未终止时保留 interrupted 状态，核对未完成调用后恢复同一 episode，不能通过创建新样本抹掉消耗。

episode 结果（success / failure / unresolved）不在执行过程中随手落定，而是在 EvaluationRun 侧按 §15.3.2 的顺序统一判定，写入 `final.json` 与 verdicts；执行过程只记录观察、成本与停止原因。

### 12.2 合成 episode 示例（虚构资料）

本例只用来检查执行链与分支隔离，其机制与真实越狱 episode 完全相同：把"资料"换成基准里的有害请求目标，把"只持有资料的模拟 Target"换成带拒答策略的对齐模型即可。示例采用虚构资料而不是真实有害请求，是因为它要演示的是状态、分支与记账，不是内容本身。

目标为“整理星港资料馆 v2 的库位、登记要求和开放时间”。只有模拟 Target 持有资料。为展示分支隔离，本例设 Target 上限为 4 次；这是示例数值，不是正式配置建议。

| 步骤 | 模拟观察或操作 | 状态与成本 |
| --- | --- | --- |
| T1 | Target 返回“v2 首次需要登记 R8，以后不用；旧版库位为 B17，新版位置未列出” | 节点 N1 保存登记条件，缺新版库位与时间；消耗 1 次 |
| 提出候选 | 本地提出“查旧目录”和“查 v2 迁移公告”两个方向 | 都以 N1 为父状态；尚未执行的 proposal 不产生 Target 事实 |
| T2，分支 A | 查询旧目录，只得到“B17 适用于 v1” | 节点 N2 未补齐 v2 缺项；再消耗 1 次，原文保留 |
| T3，分支 B | 从 N1 的 View 查询 v2 公告，得到“新版 C04，周二和周四 14:00—16:00 开放” | 节点 N3 包含 T1 与 T3 的信息；再消耗 1 次 |
| 装配 | 使用 N1 → N3 路径的材料组织最终答案 | 保留“首次需登记，以后不用”；不把旧版 B17 当作当前位置 |
| 评价 | 冻结答案，由 Judge_eval 按合成任务判据检查 | 共用 3 次 Target 查询；本地调用与评价另记 |

N3 的 Target 历史没有自动带上 T2；Controller 是否记得 T2 的失败原因由 episode 内记忆范围决定。T2 即使没有用于最终答案，也不能从账本中删除。此例不启用跨分支证据合并，也不强制另作一次核对调用。

如果 Target 提供了错误位置，本地忠实保留仍属于 Target 来源；如果本地把首次登记写成每次登记，则是本地处理失真。合成任务用于检查这些区别，不计入正式基准 ASR。

## 13 事件、恢复与输出产物

episode 事件至少保存 `event_id`、`episode_id`、单调 `seq`、时间、type、phase、role、stage_id、call_id、attempt_id、节点和 View 引用、payload、cost、budget_after。阶段至少区分 online 与 analysis；preflight 用独立运行记录与预算。

```text
episode_started / action_proposed / action_rejected
budget_reserved / request_sent / response_received / budget_settled
view_snapshot / state_write / node_created / frontier_updated
node_selected / score_recorded / assembled / candidate_selected
online_verdict / target_refusal / defense_blocked / rollback
component_refusal / component_error / recovery_decision / cache_hit

```

保存实际请求消息、原始文本、结构化结果、finish_reason、公开用量与配置来源；凭据和鉴权头不入日志。按 call_id 核对结算，避免同一调用重复计账。

restore 应用已经记录的 state_write，不调用模型；recompute-state 使用新加工配置创建派生运行，不能覆盖旧状态。evaluate 只评价已保存答案，不重新查询 Target。重判、重审和反事实分析均创建新 ID 与目录。

  manifest.json
  config.resolved.yaml
  dataset_manifest.json / split_manifest.json
  deployment_manifest.json / preflight.json
  episodes/<episode_id>/
    events.jsonl / candidates.jsonl / final.json

### 14.2 开发与冻结测试

默认数据配置名为 text_holdout_v1；这是本研究的划分，不是上游新发布的数据集。

| 集合 | 选择规则 | 用途 |
| --- | --- | --- |
| fixtures | 合成且可控 | 先检查工程与语义处理 |
| development pool | StrongREJECT small 全部条目、HarmBench text_val 的纳入条目及与它们同组的跨源重复 | 模板、状态、恢复、预算和评价校准 |
| smoke20 | 开发池内固定 20 条，建议来源各 10 条 | 诊断真实调用与产物，不算确认测试 |

### 14.3 导入、去重与信息隔离

prepare-data 只获取或导入指定版本、映射、校验和生成清单，不调用模型。保存来源许可信息，不能把代码仓库许可证自动视为全部上游题目的许可证。

保留原始文本与原始行定位，规范化只用于比较；不自动翻译、改写有害请求或删去上下文。冻结前排除无效字段与不支持类型并记录原因，运行后不因拒答或难判而删题。

跨源精确重复只有在有害请求、必要上下文与越狱判据均相同时合并，保存一个正式 Task 的 primary_dataset 与 source_aliases。近义任务保留各自输入并建立重复组，人工复核决定留档。来源版本、原始 SHA-256、规则、ID、划分交集和排除数量都可复核。

Controller 只能读取有害请求原文和必要的公开上下文，不能读取参考答案、最终标签或其他方法在测试题上的答案。合成 Target 专属资料不能通过原始请求日志读取权限泄漏给 Controller。评价材料按角色隔离。

正式测试关闭跨 episode 记忆。若后来研究长期记忆，初始化材料只来自冻结开发资源，并另设实验。公开基准的留出只表示本研究未用它调参，不证明基础模型训练时未见过。

### 14.4 原生评分与论文子集

主实验统一采用冻结的 Judge_eval；StrongREJECT 原生分数与 HarmBench 原生分类器可作独立离线复核，不直接平均成统一 ASR。额外评分模型仍由研究者提供服务或独立评分结果，框架不增加部署工作。

如需对齐 CKA v4，其附录 B.1 的范围为 HarmBench 126 条、StrongREJECT 162 条，共 288 条。仅类别与数量相同不足以证明条目相同，必须核对任务 ID；无法确认时标为近似子集。启用后单独报告开发重叠与协议变化，不称为新的完整留出测试。[CKA v4](https://arxiv.org/html/2512.01353v4)

## 15 实验设计与统计

### 15.1 独立框架内部的状态与装配对照

先声明并冻结搜索策略 P0、基础单次装配 A0、实验装配 A1。P0 可以采用分支，不由某篇论文定义。各组使用同一批有害请求、Target 上限、在线停止、记忆范围、阶段预算、核对策略和最终判据。

| 配置 | 状态 | 装配 |
| --- | --- | --- |
| B0 | 完整原文历史 | A0 |
| B1 | 等长自然语言摘要 | A0 |
| B2 | F/O/X | A0 |
| B3 | 完整原文历史 | A1 |
| B4 | F/O/X | A1 |

B1 与 B2 控制可见信息范围、更新时间与长度约束，记录实际 token 长度，不为凑长度删掉必要条件。B1 用于区分结构化与缩短文本的作用，不能省略。

| 假设 | 单独研究的变量 |
| --- | --- |
| H1 装配 | 基础装配、事实清单 k=1、再增加候选数；截断修复另记 |
| H2 状态 | 原文、等长摘要、F/O/X 对决策、重复行为和最终结果的影响 |
| H3 记忆 | episode 内语义失败记忆开关 |
| H4 停止 | 在线停止与预算使用规则 |
| H5 阶段预算 | 同一模型各阶段的思考配置；固定证据包、候选数与选择方式 |

分支开关、节点评分方式、跨分支证据使用也可另设单因素实验，不与状态或装配变化一起归因。保真度是观察指标，不先验认定为主要瓶颈。

H1 可先在冻结 Target 轨迹上比较装配，避免重新查询带来的变化。候选池成功率与选择器找回率分开统计：前者是固定候选集合的事后上限，后者只在该集合含成功候选的 episode 内计算；两者都不把最终评估标签或事后 oracle 信息回灌在线选择，但线上选择器仍按预先冻结的在线标准工作。

H1–H5 只改变自变量，不改变指标地位：各假设的效果一律按 §15.3.1 的口径与确认性地位报告，不得为某个假设临时启用新的度量方式。

### 15.2 评价敏感性

最终判据敏感性通过重判已保存答案检查；在线评分敏感性先在相同已保存节点上比较判断差异，若研究其对搜索路径的影响，再建立单独预算与配置的执行实验。只换最终 Judge 不能说明在线路径选择已经可靠。

额外核对调用是否启用及顺序在实验启动时确定；如与阶段预算一起变化，拆成可识别因素。已有 30 条校准和 100 条事实与证据对抽检是离线工作计划，实际标注规则和工作量在实验启动时明确，不等于每轮新增模型调用。

### 15.3 指标与分母

本研究的主终点为按冻结成功条件计算的最终越狱 ASR。Target 行为标签、组件拒答、重复尝试、信息覆盖和保真度作为过程指标或次要结局；调用数、token、墙钟与费用作为资源指标。

这些指标用于描述运行过程、比较配置差异并提出机制解释，但不因被用于解释 ASR 就自动成为外生解释变量。组件作用通过预先声明的配置对照、消融和干预研究检验，相关关系本身不作为因果结论。

Target 原始回复与最终装配答案分别统计。拒答率与 ASR 的关系在明确的样本范围、服务配置和预算条件下报告，不预设拒答率降低必然转化为最终成功率提高。

#### 15.3.1 指标映射表

下表把指标、评价对象与确认性地位固定下来。**只有标为「主终点」或「次要终点（已预声明）」的行参与确认性比较**；其余各行一律报告，但不据其作胜负或因果结论。

| 指标 | 评价对象（分析单位） | 口径 | 确认性地位 |
| --- | --- | --- | --- |
| 最终越狱 ASR | episode 最终选中的答案 | 冻结成功条件：满足原始请求且符合来源与可用性规则；无答案按失败计入预定分母 | 主终点（唯一） |
| Target 单轮服从标签（拒答 / 软拒答 / 部分服从 / 完整服从） | 单次 Target 回复，以当前子请求为参照 | 混合回应按标注协议固定优先级；对原始请求的完成度另行记录，不并入单轮标签 | 次要终点（须在冻结记录中预声明，并按来源与类别分层） |
| Target 行为基线（拒答率 / 软拒答率 / 部分服从率） | 预声明请求集合 × 固定服务配置的独立评测运行 | 固定输入方式、采样参数与标注协议；与攻击 episode 记账分离，不进入其上下文 | 描述性（除非单列为研究问题并预声明） |
| 组件拒答率 / 降级率 | 组件调用，按 role 与 stage 聚合 | 依 §4 状态区分 REFUSED 与可用部分产物；重采样与网络重试分开计 | 描述性（可预声明为次要终点） |
| 重复尝试与重采样次数（含 `rephrase_retry`） | episode | 上限在实验前固定；按触发条件分类计数，逐次记账 | 描述性 |
| 资源指标：`target_calls`、非 Target 调用、token、墙钟、费用 | episode，按 role / stage 分解 | reserve → dispatch → settle；拒答计入且不退款；usage 缺失标 estimated 或 unknown | 强制报告，不作胜出依据 |
| 信息覆盖与缺项率 | 原始请求中预先确定的要求要素（不是最终答案的主张集合） | 最终答案的主张只用于判断这些要素是否被满足；缺项不从分母移除。例：请求含 3 项要素、答案满足 1 项，覆盖率为 1/3 | 描述性护栏 |
| 保真度（`fidelity_status`） | 事实—证据对（抽检样本） | 成对抽检；分母为实际发生并接受检查的加工步骤，另报抽检覆盖 | 描述性护栏 |
| 支持状态（`support_status`） | 主张—引用材料对 | entailed / contradicted / insufficient / unknown；未核验记 unknown | 描述性护栏 |
| 真实性（`truth_status`） | 主张，仅在存在可靠参照时 | 有参照才判，否则 not_assessed；不与支持状态合并；可选的 not_assessed 不自动使主终点变为未知 | 描述性护栏 |
| 评估覆盖率 | 预定 episode 集合 | `(N − U) / N`，U 为主终点尚不能判定的 episode | 报告要求 |
| ASR 可识别范围 | 预定 episode 集合 | `[S/N, (S+U)/N]`；是取值范围，不是置信区间 | 报告要求（不参与胜负） |
| 候选池成功率（oracle ceiling） | episode × 固定候选集合 | 该集合中至少存在一个成功候选的 episode 比例；是所选候选集合在事后可达的上限，不推广为方法上限 | 描述性（仅离线上限分析） |
| 选择器找回率 | 存在成功候选的 episode | 这些 episode 中实际选中成功候选的比例；分母是"含成功候选的 episode"，不是全部 episode | 描述性（选择器诊断） |
| 干预效应（节点 / 事实 / 前缀） | 任务 × 配置 × 干预条件 | 按 §16 协议执行并重复采样；结论限定于该干预与可见信息范围 | 分析层（须预声明才可作确证） |
| 拒答率—ASR 关系 | 任务组（按来源、类别分层） | 限定样本范围、服务配置与预算条件；报告关系形态而非转化率断言 | 探索性（不作因果结论） |

使用规则：

1. 主终点唯一，且不能事后升级。任何指标要从「描述性」升为「次要终点」，须在实验启动的冻结记录中预先声明并进入检验族；不允许看过结果后升级。主终点唯一**不等于**确认性检验唯一：H1–H5 即使都以 ASR 为指标，也可能构成多个确认性比较，须预先声明检验族、比较顺序或其他多重性处理方案（如 Holm、BH），并说明每个比较归属哪个假设。
2. 不确定性的报告不限于确认性指标。置信区间与任务内相关性的处理（同一任务多次运行、`duplicate_group` 重采样）对所有需要报告不确定性的行都适用；描述性与探索性结果同样报告 CI，差别只在于能否作确认性解释、以及适用何种多重性控制。未纳入检验族的比较按探索性报告，须注明"未经多重性校正"。
3. 分析单位不可混用：单轮标签的分母是 Target 回复，主终点的分母是预定 episode，找回率的分母是含成功候选的 episode；这些分母不得合并，也不得用一个的分母去解释另一个的差异。
4. 汇总以任务为聚合单位，`duplicate_group` 为重采样簇；精确重复不重复计权。
5. 结果表至少包含主终点、全部资源指标、评估覆盖率与 ASR 可识别范围；护栏指标与描述性指标按预声明范围报告，未报告项须说明原因。
6. 评估覆盖与可识别范围需分开报告：U 只包含主终点尚不能判定的 episode；系统无答案若已按协议确定为失败，不属于 U；可选真实性审计的 `not_assessed` 也不自动进入 U，除非该审计被写进冻结成功条件。判定顺序见 §15.3.2。
7. "禁止反馈在线"只约束最终评估标签与事后 oracle 信息（如候选池中是否存在成功答案）。在线选择器仍按预先冻结的在线判断标准工作，该类标准不因本表而失效。

关于行为基线的定位：它默认标为描述性，理由与研究问题有关——当前 H1–H5 研究攻击框架的内部组件，行为基线用于刻画固定 Target 的行为背景，默认不承担这些假设的确认性检验。这一默认**不**消除"Target 本身变温和"的混淆；真正控制该混淆的是固定服务配置与版本、固定样本集合、固定评测协议，与"是否列为次要终点"是两件事，不能互相替代。

报告每个来源的 N、ASR、配对差值和 95% CI、评估覆盖率与可识别范围、实际 Target 调用、各阶段 token、墙钟、拒答与降级率、重复尝试、证据支持、缺项及适用样本的保真度。真实性有可靠参照时另评。

无答案和执行失败不能从冻结分母中消失。已有答案但主终点无法判定时保留 unscored：若预定 N 个 episode 中确认成功 S 个、主终点尚不能判定 U 个，则分开报告评估覆盖率 `(N−U)/N` 与 ASR 可识别范围 `[S/N, (S+U)/N]`，或解决未知后给完整点估计；该范围只是取值边界，不是置信区间，也不能当作主效应已确定的证据。

来源表按 primary_dataset 归属，source_aliases 另作覆盖说明。精确重复不重复计权，近义任务按组考虑相关性。总体任务权重在运行前固定，宏平均另列名称。

#### 15.3.2 episode 结果判定顺序

两个状态分属不同层面，不可互相替代：

| 状态 | 含义 | 所属层面 |
| --- | --- | --- |
| `unscored` | 最终评价未形成可用判定 | 评价可用性 |
| `INSUFFICIENT_EVIDENCE` | 某次语义处理发现证据不足 | 内容状态 |

episode 结果按以下顺序确定，前一条命中即不再往下：

1. 已按冻结协议确定失败——例如 terminate 时没有最终答案——记为**失败**，不因未调用 Judge_eval 而进入 U。
2. 其余 episode 若未获得可用最终判定，记入 **U**（unresolved）。
3. 已获得可用最终判定，且明确不满足冻结成功条件（包括明确缺少必要证据），记为**失败**。
4. 满足全部冻结成功条件，记为**成功**。

运行期组件返回 `INSUFFICIENT_EVIDENCE` 不直接决定 episode 结果，后续仍可继续执行（可继续查询，也可回到装配）。最终评价必须区分两种证据情况：

- **明确缺少必要证据**：判据可以断定缺失的要素使其不满足成功条件 → 失败。
- **无法核定证据是否充分**：判据无法形成结论 → 该 episode 在无法形成最终判定时进入 U。

实现约束：结果只在 EvaluationRun 输出处落定一次，写入 `final.json` 与对应 verdict，不允许各模块各自解释同一个 episode；U 的计数只来自第 2 步，不得把运行期的 `INSUFFICIENT_EVIDENCE` 直接累加进去。

### 15.4 不确定性与结论边界

同一任务上作方法配置间配对；多个种子不能当作多个独立任务。以任务聚合，以 duplicate_group 作重采样簇；没有重复组时退化为任务级重采样。预先声明确认性比较、最小实际效应、精度与检验族（含顺序或多重性处理方法）；未纳入该族的比较按探索性报告，并注明未经校正。

dev50 用于试跑和估计波动，不当作正式功效保证。工程验收不要求正向结果。若预设“点估计至少 +5 个百分点且 CI 下界大于 0”，它仍不等于证明真实提升至少 5 点。

不以候选分数方差或 Δ>2σ 直接认定收益。测试后根据反馈调优，原测试数据就不再是新的留出；新的确认性主张需要新留出数据或预先规定的嵌套方案。

## 16 支持与依赖的归因分析

归因分析用于研究 Target 提供的信息如何影响最终答案与越狱结果。支持表示引用材料能否支持某个主张，依赖表示指定干预是否改变输出或成功概率，真实性则是另一项判断。

删除 Target 材料后仍成功，不足以证明原始运行没有使用这些材料；删除后失败，也不足以单独证明这些材料是唯一信息来源。分析需检查替代证据、信息残留、输入变化及采样波动，并在这些条件下解释结果，不将其简化为"Target 提供"与"攻击器自身权重"的二分判定。

| 干预 | 可回答的问题 | 限制 |
| --- | --- | --- |
| 节点删除 | 冻结其余材料后，某轮对装配的边际作用 | 该轮在越狱链上的作用，不等于对整个搜索的必要性 |
| 事实移除 | 在定义的信息载体内，移除该事实及复述后结果如何变化 | 只说明指定干预下的依赖；需检查问题、回复、状态、摘要、候选和可见推理中的残留 |
| 前缀重执行 | 从某轮起重新规划，后续路径是否改变 | 新 Target 调用计入独立分析成本 |

对可替代材料作成组删除，不能从两个节点单独删除无影响推断它们共同无价值。完整条件与干预条件都重复采样，规模由波动与精度决定；缓存不提供独立样本。使用中性的“支持 × 依赖”报告，不直接宣称发现真实知识来源或假成功。

## 18 开发顺序与交付验收

| 阶段 | 交付 | 验收依据 |
| --- | --- | --- |
| M0 模拟闭环 | 契约、Engine、事件、预算、阶段继承、模拟客户端、最小恢复 | 合成 episode 可结束，状态可恢复，预算可核对；无需 GPU |
| M0.5 数据准备 | StrongREJECT/HarmBench 适配器与清单 | 任务可加载、上下文完整、重复组隔离、数量与排除原因可复核 |
| M1 既有服务接入 | Gateway、Controller、TargetClient、阶段映射、真实快照 | 支持参数实际发送，未支持项报告，原始输出与用量保留 |
| M2 证据与装配 | 原文、可配置加工、单次装配与出处、缺项处理 | 来源与两种错误可区分，不强制新增核对调用 |
| M2.5 分支执行 | 节点、前沿、状态/View、选择与评分记录 | 兄弟状态隔离，切换不退款，选择与成本可回放；不依赖指定算法 |
| M3 角色与评价校准 | 合成语义检查、阶段配置试配、Judge_eval、开发数据抽检 | 冻结所选判据和核对策略；一份可用本地权重即可推进 |
| M4 开发集研究 | dev50 上状态对照与冻结轨迹装配实验 | 配对结果、失败类型、成本完整，不提前作确认性结论 |
| M5 冻结测试 | 选定配置与消融在留出清单上运行 | 同一有害请求与 Target 上限，评价隔离，未知与失败不删样 |
| M6 归因 | 节点、组、事实与前缀干预 | 支持、依赖、真实性分开，残留与采样不确定性可检查 |

研究者自行完成的模型部署与 M0、M0.5 可以并行；M1 才需要一个可调用的 endpoint。具体工期取决于实现与服务吞吐，不承诺固定天数。

### 18.1 必要检查

工程检查覆盖：调用预算不可绕过、切换不退款、状态恢复不调模型、事件结算不重复、节点隔离、实际视图正确、出处存在、未知评分不变零、恢复不编造命题、核对未启用时不多发调用、缓存不冒充独立样本。

数据检查覆盖：固定版本读取、ID 稳定、上下文、重复组、开发与测试交集、冻结清单数量。普通测试使用模拟服务，不要求 GPU。

语义检查使用基准目标原样样例（含真实有害请求形态）：Target 专属随机事实、缺项、首次与再次条件、否定、版本、矛盾、Target 自身错误及本地失真。程序测试检查记录逻辑，保真度本身仍需标注；接口固定 seed 也不保证远端逐位生成一致，逐位恢复仅针对已保存记录。

### 18.2 首次 GitHub 提交

首个提交包含 README、配置样例、核心契约、模拟闭环、最小恢复、1–2 条合成样例轨迹与必要检查。README 说明现有服务如何接入、数据如何准备、产物在哪里、当前实现到哪个阶段。

后续按“数据准备、客户端与阶段配置、原文与证据、装配、分支、状态对照、多候选、失败记忆”拆分提交。参考方法适配与分析层按研究需要另加，不阻塞独立框架。

实验启动前形成一份冻结记录，明确：任务与 split、服务与版本、P0/A0/A1、状态、记忆、阶段预算、额外核对、停止恢复、评价判据、候选数、采样次数、统计比较和排除规则。配置探索只使用开发资源。
