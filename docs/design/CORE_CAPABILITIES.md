## 1 如何记录状态

每项能力分别记录四个维度，不能合成一个含糊的“已完成”：

- 实现：未实现 / 骨架或部分 / 主流程已接入。
- 启用：哪个具体配置启用；无已选配置则记“未选定”，不能猜当前活动批次。
- 验证：静态核对 / 开发者报告 / 离线行为复跑 / 真实运行核验。可同时具备多个证据，不由较低级证据替代较高级证据。
- 研究：是否有符合协议的效果结论；真实调用成功也不自动代表有 ASR 改进证据。

以后更新时附提交、配置和可定位证据。历史状态保留在 Git；不得把本表日期更新为今天但仍沿用过期事实。

## 4 重要实现细节

### 4.1 请求、响应和分支归属按执行边关联

请求生成、实际发送、响应接收、证据生成各有不同状态。generated 但未 dispatch 的 query 不能算已询问；缓存命中也不能算独立真实调用。实际发送后失败要保留查询和成本。

建议复用现有 request_id/call_id/action_ref/response_ref 与父子节点关系建立可追溯关联，不另维护一份容易漂移的全局历史。记录 query 来源和必要响应片段；有引用却没有解析后的可读内容时，要说明 Controller 实际看到了什么。

**分支归属（已修复，b3e9514）：**`Engine.query_history` 改为按执行边归属——`call_id → 观察子节点` 索引（`_observation_node_by_call`），request_sent 挂在扩展前父节点不再导致兄弟查询误入当前分支。离线复跑验证：三次查询的当前分支/全局失败记忆划分正确，当前分支查询的观察子节点都在祖先链上。

global failure 的含义也要明确：PARTIAL、TRUNCATED 或带拒绝措辞的回复可能包含有效材料，不能一概等同“完全没有获取信息”。传输状态、行为标签、语义完成度分别存储，失败记忆是策略选择而非事实真值。

### 4.2 在线反馈必须引用正确的候选与材料版本

b3e9514 已做最小接线：`LLMController.build_input` 的 `state.candidate_feedback` 来自 `Engine.latest_candidate_feedback()`——候选 id、answer 摘录、gaps、online_verdict（decision/ratio/basis）、pack_id、`pack_input_hash`、node、`stale` 过期标记；旧渲染路径同步。未新增模型调用；反馈仍标注为待判断信息，不是成功标签。真实运行中 Controller 是否有效消费该反馈（据此继续/切换/停止）尚未验证。

建议反馈记录表达：来自哪个 candidate、哪个 pack/材料版本、哪个节点、何种检查、哪些缺项/矛盾/未知、检查版本及是否过期。字段命名可适配现有契约。

Assembler 的 gaps 是模型判断，不能自动升级为正式事实。回传后仍需 Controller/策略决定是否继续获取信息。当前子查询完成不代表原始任务完成；最终 Judge_eval 的结果不可作为这份反馈。

### 4.3 正式状态与记忆分开

raw 直接使用规定范围的原文；summary/F-O-X 必须记录真实加工及信息范围。不得一边声称摘要组，一边在另一个隐藏字段塞入完整历史，让状态对照失去含义。

保留条件、否定、版本、对象和不确定性；支持不足的本地推断进入 hypotheses。Target 的错误与本地概括改变原意分开。`verbatim` 只说明形成方式，不证明截取后的上下文完整。

失败记忆可跨允许的分支范围共享，但正式 evidence 不能自动合并。跨 episode 技能库不是当前必需项。

### 4.4 搜索策略必须在运行中做出可检查的选择

Frontier 管可选路径，SearchPolicy 管选择/扩展，Scorer 管对象与评分依据。策略不固定为 CKA 或 UCT。若使用无评分的稳定次序，就如实标注，不把它描述成语义最优选择。

当前 null/rule scorer 是基础实现。回答长、事实多、关键词命中或模型自报自信不能单独等同进展。未知评分的排序/回退必须明确；不能把 None 转成有语义的失败惩罚而不记录。

选择动作至少记录所选节点和候选范围/策略依据；只有节点结构或 visits 数变化还不能证明某种树搜索算法完整落地。

### 4.5 多候选不是 k 字段

b3e9514：`LLMAssembler.assemble_from_pack` 逐样本生成——k 个独立真实请求（k>1 时 `cache_bypass` 绕过响应缓存的查找与写入）、逐样本 attempts 与 call_id、预算中途耗尽保留已生成样本并标 `sampling_interrupted`、相同答案标 `duplicate_of_sample` 不冒充。同一冻结证据包上生成；选择由冻结在线 selector 负责。两配置仍为 k=1/first，k>1 属于待启用的实验变量。

在同一冻结证据包上生成并保存全部候选；改变证据包属于新的材料条件。不要只改 candidate_id 或排版制造“多个候选”。在线选择器不得访问最终评价，离线候选池上限另算且不反馈在线。

### 4.6 候选新鲜度不能只看最近 pack

统一收尾已经存在（independent.py:321）。b3e9514 起候选新鲜度从最终选中 candidate 的 `evidence_pack_ids` 追溯包 `input_hash`，不再使用 `engine.packs[-1]`。材料“变化”不等于“更好”，是否采用新材料由明确选择策略决定，不偷用 Judge_eval 挑最优结果。

无变化不重复装配；plan 额度耗尽仍可用 assemble 剩余额度；总额度与阶段额度分别检查。回退候选标出来源、原因和实际未执行的处理。避免多个停止分支各自追加 terminate。

### 4.7 证据包与评价范围要一致

调用前冻结装配输入、包身份和 hash；候选关联不能事后补造材料。引用到的证据可回到原始 Target 响应，query/本地 rationale 不被伪装为 Target 回复证据。

candidate_pack 和 episode_pool 是不同协议，不因某题判失败而临时替换。引用不支持主张属于语义问题；缺损产物导致无法评价属于完整性问题。checksum 不验证语义蕴含，内容来自 Target 也不验证真实性。

原始目标不因中间改写而改变。正常无答案与评价未完成的分母口径维持既定协议；记录单轮行为不影响最终指标地位。

### 4.8 模型角色、配置与预算保留真实身份

角色映射 service，阶段决定参数，不按“本地/远端”硬编码职责。Controller/Assembler 可共用同一模型，但分别构造输入和记账；Judge_eval 独立评价阶段不读取在线状态来选答案。

使用现有 services 覆盖机制；覆盖文件整项替换时不得只提供部分必需服务字段。记录实际解析配置、模板 hash、参数映射与服务身份，不记录密钥值。服务支持某参数与该参数真的生效不是同一结论。

用户已经调整上下文，本轮及当前约束下不做窗口、长输入、超窗或容量测试，不更改部署。其他已授权功能开发不能把窗口测试重新列为隐含前置条件。
