# 评审指南

按顺序看，约 30 分钟。每节末尾列了"这一节最该被质疑的点"。

---

## 1. 先看结论：这套东西要回答什么

`spec/01-goals.md`

- 目标函数是**同 `target_calls` 预算下的 ASR**，其余指标是护栏。
- 三个能力：可回放、可换件、可归因。
- 明确不做：训练栈、多模态、模型内部表征。

> 该被质疑：三个能力里有没有哪个其实用不上？"可归因"是不是被过度设计成了基础设施？

## 2. 再看契约（评审重点）

`spec/02-contracts.md`

- 数据契约 C1–C4：Episode / Event / State / Verdict。
- 接口契约 I1–I8：Target / Defense / Frontier / Scorer / Controller / StateBackend / Memory / Judge / Assembler / BudgetGuard / SessionMode。

> 该被质疑：不变量是否足够强（强到能防错），又足够弱（弱到不限制实验）？`Verdict` 里 claim 级字段是不是过重？

## 3. 运行时与预算

`spec/03-runtime.md`

- 一次 episode 的 13 步时序。
- 在线停止判定与离线评价判定**必须是两个裁判**。
- 所有模型调用必须持预算票据；运行成本与分析成本分账。

> 该被质疑：13 步里有没有多余的步骤？两裁判的拆分会不会让"在线停止"失去意义？

## 4. 实验设计

`spec/04-experiments.md`

- 五个配置：B0 基线 → B1 +摘要 → B2 +结构化状态 → B3 +新装配 → B4 +两者。
- 四个假设 H1–H4，按"提高 ASR 的可能性 × 成本"排序。
- 冻结清单：除被测项外全部固定。

> 该被质疑：B1 这一臂是否必要（我认为必要，否则分不清结构化与变短）？H1–H4 的排序是否与实际收益预期一致？

## 5. 分析与统计

`spec/05-analysis.md`、`spec/07-statistics.md`

- `support`（有无依据）与 `dependence`（删了还成不成立）分开。
- 三层反事实重放：节点 / 事实 / 前缀。
- 配对差值 + 置信区间 + 预定义效应量；缓存命中不得进入方差计算。

> 该被质疑：三层重放的成本是否被低估？"指定干预下的依赖"这个措辞是否足够诚实？

## 6. 里程碑与风险

`spec/06-milestones.md`

- M0 日志 → M1 接入 → M2 最简方法 → **M2.5 忠实基线** → M3 判定 → M4 实验 → M5 分析。
- M2.5 是硬门槛：表达不出基线的搜索，就不要谈"比基线好"。

> 该被质疑：M2.5 的 6 天是否现实？如果表达不出基线，退路是什么（改契约还是放弃比较）？

## 7. 决策记录

`adr/0001`–`adr/0005`：每个决定都写了被否决的替代方案。若你不同意某个选择，改 ADR 比改代码便宜。

## 评审时最值得直接反对的三件事

1. **claim 级判定**（C4）：它让归因成为可能，但也让判分成本翻倍。如果实验只用 ASR，是否可以先降级为"总分 + 抽样 claim"？
2. **两裁判分离**（`Judge_online` / `Judge_eval`）：合理但会让在线停止的判据变弱（在线只能用便宜判据）。
3. **B1 摘要臂**：多花两天，但不做就无法回答"增益来自结构化还是来自变短"。
