# ADR-0005：把装配提成一等接口

- 状态：已接受
- 日期：2026-11-10

## 背景

已有工作证明装配会影响结果（参考实现的作者用替换弱合成器的对照验证过：自答 38% vs 用轨迹合成 78%）。但这些实验是**一次性**的，装配没有成为可复用的实验维度——因为在实现里它是方法内部的几十行代码。

## 决定

`Assembler` 作为接口独立出来，与规划同级：

- 输入：轨迹 + 目标 + k
- 输出：最终答案，并写 `assembled` 事件（k 份候选、选中哪份、token）

## 理由

- 装配是**唯一不增加目标调用**就能改的一环，在同预算约束下性价比最高（假设 H1）。
- 装配方差（同一轨迹多次装配的分数波动）是可以直接测的量，而它决定了"多次择优"到底有没有空间。

## 后果

- 每个方法都必须显式声明自己的装配策略，不能再"藏在方法里"。
- 装配调用要计入预算与成本报告（它不花目标调用，但花 token）。

## 被否决的替代方案

1. **保持装配在方法内部**：无法跨方法比较装配策略，也无法冻结轨迹单独实验。
2. **把装配当成后处理脚本**：无法进入在线停止判定（第 12 步需要装配结果）。

## 一句提醒

装配策略已被证明会影响结果；本项目的增量不是"发现装配重要"，而是"把装配变成可系统比较、可复用的实验维度"。写作时不要夸大。
