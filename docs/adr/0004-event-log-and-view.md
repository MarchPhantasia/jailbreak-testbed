# ADR-0004：事件日志为唯一真相，回退只改 View

- 状态：已接受
- 日期：2026-11-10

## 背景

多轮攻击里常见三种需求同时存在：目标不该看到被回退的轮次；分析者要看到全部尝试；复现时要能重建当时的状态。若用"删除历史"来实现回退，第三条就无法满足。

## 决定

- 所有交互写入 append-only 的 `Event`。
- 回退写一条 `rollback` 事件，并提升 `HistoryView.view_id`；**不删除任何事件**。
- `AgentState` 的每次更新都写 `state_write`（含抽取器版本）。

## 理由

- "目标看不到、攻击者记得"不需要特判，只是同一份日志的两种读法（按 view 过滤 / 全量）。
- 反事实重放（删一个事件重放）只有在日志完整时才成立。
- 状态由 LLM 抽取产生，无法从回复逐位重建；必须记录"当时写入了什么"——即 `state_write`。回放时区分 `restore`（恢复当时状态）与 `recompute`（用新抽取器重算）。

## 后果

- 日志体积变大（每个 episode 可能包含数百条事件）。
- 必须提供按 view 过滤的读取器，否则分析时容易误用全量历史。

## 被否决的替代方案

1. **物理删除 + 快照**：快照无法覆盖"删除后又想恢复"的分析需求。
2. **只记最终对话**：反事实重放做不了，归因退化为猜测。
