# ADR-0001：从零构建，不 fork 任何现有项目

- 状态：已接受
- 日期：2026-11-10

## 背景

候选路线有三条：fork 一个现成的攻击框架、在自家已有实现上改、从零写。

## 决定

从零写。外部项目只作**设计参考**，不引入其代码。

## 理由

| 项目 | 若 fork 会遇到的问题 |
|---|---|
| CKA-Agent | AGPL-3.0（传染性）；依赖未声明；仓库快照早于论文修订版，口径不一致 |
| MT-JailBench | MIT 可用，但其 engine 结构与我们要的分层不同，改造量接近重写 |
| MemoAttack | 无许可证，代码不可再分发 |

更根本的理由：我们要的能力（事件即真相、预算即因子、主张级归因）是**架构级**的，不是功能级的。在别人的架构上加这三样，等于重写。

## 后果

- 前期慢 2–3 周，且这段时间没有论文产出。
- 换来的是：换件成本趋零、结论可回放、许可证干净。
- 参考项目的具体借鉴点写在各自的 ADR 与 `docs/spec/` 中，并注明"仅借鉴设计"。

## 被否决的替代方案

1. **fork MT-JailBench 加插件**：快，但它的 Turn/Attempt 模型与我们的 View 语义不同，且没有事件日志，反事实重放做不了。
2. **在 CKA 上加 instrumentation**：最快出数，但结论只能覆盖一个方法，且许可证限制发布。
