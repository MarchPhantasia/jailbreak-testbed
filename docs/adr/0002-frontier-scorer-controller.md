# ADR-0002：搜索拆成 Frontier / Scorer / Controller 三个接口

- 状态：已接受
- 日期：2026-11-10

## 背景

若把"选哪个节点""给节点打分""决定继续还是重试"写在一个类里，那么"换打分策略"和"换搜索策略"就无法分别实验——而这两个正是最常被比较的对象。

## 决定

拆成三个独立接口：

| 接口 | 职责 | 可替换实现举例 |
|---|---|---|
| `Frontier` | 从前沿里选出要扩展的节点 | UCT、best-first、BFS、线性推进 |
| `Scorer` | 给一次交互打分 | 混合评分（自省 + 目标反馈）、ΔF/Δc、纯信息增益 |
| `Controller` | 控制流（继续/重试/回退/停止） | 阈值停止、预算耗尽停止、固定轮数 |

## 理由

- 只有拆开，"打分是否被自评带偏"才是可检验的（自省项与出题人是同一个模型，这是可测的具体问题）。
- 只有拆开，才能把参考实现原样表达出来，进而比较（见 `06-milestones.md` 的 M2.5）。

## 后果

- 接口多了三个，配置项变多；用 YAML 默认值缓解。
- 某些实现会把三者耦合（例如 MCTS 的 rollout 同时承担打分与控制），接入时需要一个薄适配层——这是可接受的成本。

## 被否决的替代方案

1. **单一 `Agent` 类 + 策略模式**：实践上仍会把打分层留在类内部，实验时改不动。
2. **只拆 `Scorer`**：解决了打分实验，但解决不了"搜索宽度/回退策略"的实验。
